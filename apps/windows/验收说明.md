# PausePal Windows 集中验收

本轮按用户决定，先完成 Windows 迁移测试版，由用户集中验证真实使用。Mac 已有结果不计为 Windows 通过；手机继续使用 S25 已安装应用，不重装、不改签名。

2026-10-20：用户的 YouTube 失败已复现。输入监测正常，系统辅助功能读取的进度可能冻结或缺少播放控件；0.1.1 仅改进故障提示与本机诊断，**没有修复暂停／恢复**。暂不要求用户重测相同失败链，也无需新增输入权限。原 `.local/windows` 包未被覆盖；诊断构建单独保存在 `.local/windows-diagnostics`，不自动替换运行中的程序。

## 启动与配置

1. 双击项目 `.local/windows/PausePal.Windows.exe`。整个目录需要保留；本机已具备 .NET 10 Desktop Runtime。
2. 在任务栏通知区域（可能收在向上箭头内）找到断链图标，右键确认局域网服务已注册。没有主窗口。
3. 若 Windows 防火墙弹出询问，为该程序允许**专用网络**。手机和电脑连接同一家庭局域网。程序不会自动改防火墙、网络类别或路由器。
4. 手机打开现有 PausePal，在电脑列表选择 `PausePal-电脑名`，电脑弹出首次配对窗口后点“允许”。手机现有版本的部分提示仍称 Mac，这是已登记的 Android 文案问题，不需要在 Windows 覆盖安装。
5. 登录后启动默认开启。右键托盘可关闭，选择会保存；退出后重新打开不应丢失电脑身份，也不应重复要求已成功配对的手机批准。测试包未签名，不伪称安装版或已通过系统信誉验证。

程序首次启动自动建立独立的 Windows 电脑身份，无需填写地址、端口、令牌或导入 Mac 证书。身份在当前用户 `%LOCALAPPDATA%\PausePal\identity.dpapi`，不要删除或分享。更新时保留该文件；启动失败不会自动重建身份。

## 一次测试顺序

- **连接与四态：** 未连接为断链；连接未开始为空心绿眼；手机开始并看屏幕为睁眼，侧看/闭眼为闭眼；识别未知或停止为空心；断线恢复断链。图标表达手机方向，不等于播放器状态。
- **开始不播放：** 在 Chrome 手动暂停 YouTube，手机开始识别、转头再回看，视频应保持暂停。
- **连续观影：** 手动播放视频并保持它为实际前台，手机转头/回看连续 3～5 轮。每轮应自动暂停，明确回看后恢复；确认恢复后仅尝试一次回退，回退无法安全执行时可跳过。记录停在哪一步及托盘媒体状态。
- **接管保护：** 自动暂停后手动点击/按键，或换标签/换片，然后回看；不能恢复旧暂停。分别测试手机停止、断开和重新连接，不能补播，重连必须重新开始。
- **播放器范围：** 同样检查 B站及本地播放器。当前旧版 Windows Media Player 已知缺少可核验播放项/时间线，程序会拒绝控制，不能把它登记为通过。未知、多义、结束或无法独立核验时间线的媒体也可能被拒绝；不要为了测通而放宽手动暂停保护。
- **托盘与启动：** 检查深浅色任务栏、当前缩放比例下四态清晰；关闭再打开自启开关，退出后重新启动检查偏好和配对保持。登录后启动的实际生效需在方便时注销/重新登录核对，不必为本轮开发反复重启电脑。

## 失败时记录

只需告诉 Codex：播放器、失败步骤、大致时间、托盘媒体状态。程序已在本机保存有界诊断，位于 `%LOCALAPPDATA%\PausePal\logs\receiver.log`，另保留一个前轮文件；每个最多约 2 MiB。诊断含采样进度、截止时间、固定状态与错误类型，不记录页面地址、原始消息、手机名、会话、令牌或图像。

这些日志和本机界面预览不上传公开仓库。无需上传私人视频或账户截图。最新版此前的媒体进度核验失败仍待此次真实验收，新日志用于区分观察值不推进、采样超时、输入接管和目标变化。
