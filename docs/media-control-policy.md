# 桌面媒体识别共用规则

2026-10-21，适用于 Windows 和 Mac 的后续优化。用户只在观影时开始使用 PausePal；开始表达观影意图，具体目标和后续暂停／恢复仍由桌面逐轮确认。协议及手机交互不变。

## 共用行为

1. 不要求网站给播放器容器起特定名称。名称可以提供媒体线索，不能成为唯一必需条件。
2. 目标属于当前实际前台顶层窗口及活动文档分支。同一播放器的嵌套文档是层级关系，不因存在多个文档就认定多个播放器。播放控制、seek与时间来源必须属于同一最近Document；文档祖先链用于关联上下文，不授予跨最近Document拼接证据的许可。兄弟框架不共用时间、进度或焦点证据。
3. 无名结构路径只接受完整的局部控件组：唯一明确播放控制、唯一时间进度、唯一音量及媒体动作；播放、时间进度、音量直接同组。可见后代有无关正文、导航、其他控件或文档时不授予该路径资格。既有明确媒体名称路径属于另一路证据，不能把名称存在解释成任意控件均可被控制。
4. 只向已识别的具体控件提交固定动作。状态不明或多个目标时不猜测，不发全局盲切换，不增加扩展、站点脚本、网站名单或音频评分系统。
5. 开始不播放；明确播放时可单次暂停，必须确认同目标已暂停后才考虑恢复。恢复仍须有效且未结束的位置锚点、同目标、无接管、健康输入观察和及时采样。结构识别成功不是恢复资格。
6. 手动键盘、点击、滚轮及换目标只撤销本轮自动资格，观影保持。用户手动继续播放后再次离开可建立新轮；初始手动暂停不自动播放，停止／断线／重连不补播。UNKNOWN不凭空授予资格。
7. 时间数值必须有可解释单位和范围，缺失与结束分开。无单位滑块不自行当作秒，来源冲突或无法核验就取消恢复；不为看似测试通过而放宽。
8. 恢复成功后才最多尝试一次回退。回退能力独立，焦点不安全或时间能力不足时跳过，不能补发播放动作。

## 各平台的实现责任

Windows 将 UIA 节点映射到本地能力，保留 HWND、进程、文档链、局部组及控件身份；Mac 用 AX 节点和实际应用窗口上下文实现相同含义。UIA 的 Group 与 AX 的 AXGroup/角色描述并不完全等价，平台名称正则不能直接互相复制。

共用合成用例在 `tests/media-policy/cases.json`。其中结构用例验证无名组、跨分支拼接和多控制歧义；文档用例验证同分支、兄弟框架与外层文档变化。Windows 已将该文件接入自动回归；Mac 尚未实现适配和执行，不能登记为通过。用例不包含真实网页、运行标识或私人媒体。

这组用例只描述辅助功能控件组和资格边界，不证明发现了实际 video 元素。控件、上下文、时长及暂停位置全部相同的原地换片，仍可能无法从现有观察面区分；观察到执行之间也有平台竞态。遇到证据缺失应准确报告，不以更多合成通过消除边界。

## 当前真实缺口

Windows 在 Chrome 原生视频样本中采到无名 Group 内的暂停、时间进度、音量、静音、全屏和更多媒体控件；组直接属于 Document。采样未取得完整时间描述，只有部分已播放时间描述和 RangeValue；同时视频源发生缓冲／播放错误。因此尚不能证明该类播放器具有有效暂停锚点及连续恢复能力。

下一步需要在稳定可播放的原生视频上核验平台时间能力，必要时研究有明确单位合同的系统接口。不能仅因数值看起来像秒，或其他平台通过，就将它当作已解决。该缺口与容器名称误拒分开跟踪。

暂停位置锚点在概念上不必以秒计量，5秒回退才依赖秒单位；但不能据此直接接受任意RangeValue。滑块可能使用默认0～100范围、百分比或直播可移动窗口，有限范围不证明完整媒体端点；百分比固定范围还会失去原有时长变化的换片线索。[WAI-ARIA slider规范](https://www.w3.org/TR/wai-aria-1.2/#slider)明确允许缺省范围。因此未来的无单位锚点方案须另行证明具体能力、媒体身份及结束边界，经审查后再实施；0.1.3没有采用这一泛化方案。

## 验收分层

各平台分别记录：静态检查、构建、共用合成用例、系统辅助功能实测、真实媒体连续暂停恢复、手机普通入口。至少包括无名原生控件、已有播放器回归、嵌套文档、兄弟框架时间／焦点、手动接管及后续新轮、初始暂停、结束和断线。Windows 结果不继承为 Mac 结果。
